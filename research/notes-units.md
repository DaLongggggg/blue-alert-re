## 1. ID → 中文名（两作同表）

- **g1**：`FUN_0042b180`（0x42b180.c）。ID≥1000 → 0x4a1784「技术值增加500」；
  否则 switch(param_2) 直接映射 ID 1–34、40–46、100–115 → .data 字符串（见构建脚本 `UNIT_CN_G1`，出处为反编译 case 表）。
- **g2**：名称函数在 0x429b80 起（0x429ba6 `cmp eax,0x3e8`；0x429bcb `dec eax; cmp eax,0x72;
  mov cl, byte [eax+0x42a178]; jmp [ecx*4+0x42a090]`）——**字节表 0x42a178 + 跳表 0x42a090**，
  解出的 ID 映射与 g1 完全一致（构建脚本 `UNIT_CN_G2`，两作中文名做了逐条一致性断言）。
  ⚠️ 直接按跳表顺序读会得到"重编号"的假象（跳表 58 项是按 case 号而非 ID 排列），必须经过字节表。
- ID 空间：
  - 1–15 陆地单位（轻型→重型：防空设施/炮兵/装甲坦克/喷火器/特派坦克 各3级）
  - 16–18 金币流入1–3；19–21 研究指数流入1–3；22–24 能量流入1–3（建筑生产模式）
  - 25–29 炮塔：防护大炮/防空设施/离子炮塔/莱德风暴/集束炮塔
  - 30–34 空袭：轰炸机袭击/运兵飞船/战斗机袭击/连环轰炸机轰炸/星体炸弹风暴
  - 40–46：飞碟/科迪亚克/空对空复仇者/美洲狮/格林机关炮/阿基里斯/罗根炸弹
  - 100–108：总部/轻型工厂/中型工厂/重型工厂/飞机生产基地/金矿/太阳能搜集器/风能搜集器/机器人工厂
  - 109–113 Top Sentry G10/A20/G30/G40/G50；115 缩略地图（界面元素）
  - 114 与 35–39、47–99 无名字（空串）。
- g2 字符串区：中文名 0x49e5fc–0x49e894，英文名 0x49e28c–0x49e5dc，与 g1（中文 0x4a14ec–0x4a1778，
  英文 0x4a117c–0x4a14cc）内容逐字相同。

## 2. 英文名（nameEn）

- g1：英文名函数（0x42ab34 起）：`cmp eax,0x3e8 → 0x4a14cc 'increase tech-level for 500'`；
  `dec; cmp 0x72; mov cl, byte [eax+0x42b108]; jmp [ecx*4+0x42b020]` —— 字节表 0x42b108 + 跳表 0x42b020，
  完整解出 49 个 ID 的英文名（构建脚本 `UNIT_EN_G1`，转储 research/mining-g1-enname-pairs.txt）。
- g2：英文函数 0x429570 起，字节表 0x429b28 + 跳表 0x42a040，抽查 ID 1/7/25/31/34/40/46/100/107/109
  全部与 g1 同名同 ID。
- 注意汉化对照并不直译：飞碟=**Advancer**、太阳能搜集器=**Research Lab**、风能搜集器=**WindTrap**、
  飞机生产基地=**Air Navigator**、金矿=**Gold Mine**、运兵飞船=**CarryAll**、
  轻型装甲坦克=Light **Panzer**、莱德风暴=**LedStorm**、星体炸弹风暴=**Meteor Storm**。
- 另有孤立串 `'n/a'`(g1 0x4a1794 / g2 0x49e8a4)，未收录。

## 3. InfoBox 资料框说明

- **g1**：`FUN_00437130`（0x437130.c）：`switch(param_2)` 直接给出 ID→说明串。
  覆盖 1–34、41–46、100–108；**ID 40（飞碟）无说明**；**20/21（研究指数流入2/3）与 19 不同、共用同一条**
  「这种模式一次能增加一个研究指数」（19 用「两个」，两作如此，照录）；109–113、115 无说明。
- **g2**：说明函数 0x43570c 起：`lea eax,[ecx-1]; cmp eax,0x6b; ja 0x435919;
  mov dl, byte [eax+0x435a18]; jmp [edx*4+0x435954]` —— 字节表 0x435a18 + 跳表 0x435954（49 项，
  case 48=空串）。映射与 g1 相同（含 40→空、20/21 共用）；构建脚本对两作说明文本做了逐条一致性比对。
- g2 轻型防空说明在扫描时被分成 0x4a0b38 + 0x4a0b80 两段（GBK 边界），构建时自动拼接。

## 4. 分类（category）

依据名称+InfoBox 说明人工判断（每条 sources 里写了依据）：
- defense：1–3（防空设施）、25–29（五种炮塔）、109–113（Top Sentry 塔炮）
- land：4–15（炮兵/坦克/喷火器/特派坦克）、41–45（超级机器人/空对空机器人）
- air：30–33（轰炸机/运兵飞船/战斗机/连环轰炸机）、40（飞碟）
- superweapon：34（星体炸弹风暴）、46（罗根炸弹）
- factory：101–103（轻/中/重型工厂）、104（飞机生产基地）、108（机器人工厂）
- building：16–24（三种「流入」模式）、100（总部）、105（金矿）、106（太阳能搜集器）、107（风能搜集器）
- other：115（缩略地图）、25 条武器名
边界说明：16–24 是建筑的生产「模式」，归入 building；34/46 是可造成大范围毁灭的弹药类，归 superweapon。

## 5. 武器名表

- g1 `.data` 0x4a1798–0x4a18ec：25 条英文名（4x AG bombs … 2x antiair rockets）；
  g2 `.data` 0x49e8a8–0x49e9ec 同表（转储核对一致）。全部按 category=other 收录，name=英文原文。
- **武器 ↔ 单位的对应关系未考证**（需逆向单位构造/攻击代码或 .srf/地图数据），所有条目 weapons=[]。

## 6. 数值属性（stats）结论

- 在 `.data` 0x49f900–0x4a8000 范围内除字符串/指针 UI 数据外，未发现「名称↔数值」形式的静态属性表；
  简报/名称/说明均为纯文本串，旁边没有数值数组。
- 判断：单位数值（生命/攻击/射速/造价等）更可能存在于各单位类构造函数的立即数或关卡/SGV 数据中；
  可靠读取需要逐个单位类逆向（数量大）或动态验证，超出本次任务时间盒。
- 因此所有 units 条目 stats=[]（留空），未臆测任何数值。后续若做：入口建议从
  名称函数 FUN_0042b180 的调用方（UI 刷新链）找 CPart 对象，再沿虚表定位属性成员。
